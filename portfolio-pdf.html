Regulatory deadline · 5 Oct 2026

Digital transport documents with a scannable QR code

Spain's Sustainable Mobility Law 9/2025 requires the transport document to be digital and scannable by roadside inspectors. Bringg had no route-level document, no QR code and no way to tell a customer's system about one.

I took this from design document to production across 6 services. When a driver starts a route, the platform generates a compliance PDF, stores it for 7 days after the route ends, and sends the driver app a link it turns into a QR code on the device, so it works offline. The customer's systems get a webhook when the document is ready.

I designed the database schema and an idempotent write path (one document per route, enforced in application code), added server-side PDF rendering to the templates service, resolved the right truck and trailer plates for each route, and wrote the test plans and integration guide for the webhook. I am now extending the end-to-end automation to the webhook and the QR code on mobile, repeating each test 50 times to prove it is stable.

  1. Driver starts a routeThe core platform publishes a route-started event.
  2. Eligibility check and claimA Node.js service reads the merchant and team configuration, then claims the route so a retry never creates a second document.
  3. PDF renderThe templates service builds the document with vehicle and trailer plates and renders it through Gotenberg.
  4. Store and notifyThe document is saved with a token and a retention date. A documents_ready webhook goes to the customer and a real-time update tells the driver app.
  5. Roadside scanThe inspector scans the QR code. A token-guarded URL returns the PDF, or a clear error when it has expired.
